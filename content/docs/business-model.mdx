## Principles

The open-source CLI should be genuinely useful. Monetization should come from convenience, history, automation, privacy controls, integrations, team governance, and enterprise operations—not from artificially breaking the core CLI.

## Free — $0

Keep free/open-source:

- CLI
- local receipt generation
- JSON output
- JSONL export
- Git hooks
- basic provider adapters
- basic public receipt cards
- GitHub Action
- local-only mode
- export/delete controls

A free developer should be able to use Qodewk without paying.

## Pro — $10/month

Candidate features:

### History

- 30/90/365-day history
- personal trends
- project-level trends
- model/provider breakdown

### Automation

- daily standup
- weekly summaries
- monthly reports

### Privacy/customization

- private historical analytics
- custom receipt branding
- custom themes
- custom domain/username options

### Integrations

- Slack
- Discord
- Notion
- GitHub
- Linear

## Team — $25/seat/month

The buyer is the engineering organization, not the individual developer.

Features:

- organization budgets
- project budgets
- per-team spend caps
- model allow/deny policies
- spend alerts
- team-wide analytics
- audit history
- role-based access
- SSO/SCIM at higher tier

## Kill-switch reality

Qodewk cannot universally kill every external agent. Enforcement depends on available control surfaces.

Correct product promise:

> Detection everywhere; policy enforcement where supported.

For integrations that expose budget/gateway/policy mechanisms, Qodewk can drive enforcement.

## Enterprise

Potential features:

- SSO
- SCIM
- RBAC
- audit logs
- configurable retention
- data residency options
- self-hosting/private deployment
- SIEM export
- custom pricing models
- custom provider rates
- policy API

## Monetization priority

1. Pro subscriptions
2. Team governance
3. Enterprise compliance/self-hosting
4. Usage-based cloud features only where cost is real

Do not rush into an ad-supported developer tool.
