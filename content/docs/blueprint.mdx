The transition from deterministic manual programming to autonomous, agentic software engineering has fundamentally altered developer tooling economics. In 2026, software development has shifted from manual text entry within traditional Integrated Development Environments (IDEs) toward multi-agent systems executing across editors, terminals, and headless browser sessions1.

Concurrently, artificial intelligence infrastructure vendors and developer tooling platforms have moved away from flat, predictable per-seat monthly subscriptions toward dynamic, metered, consumption-based billing models governed by context-window volume, cache utilization, and multi-turn reasoning overhead3.

This economic shift has introduced significant friction into software organizations. Engineering managers face unpredictable bill shocks as agentic reasoning loops consume API credits asynchronously5. Solo developers lack visibility into the compounding micro-costs of exploratory agent tasks3. Engineering teams operate without a unified telemetry layer to audit machine-generated code churn1.

Existing telemetry solutions are fragmented. Single-vendor diagnostic utilities such as Chit operate exclusively by reading proprietary local JSONL session transcripts generated by Claude Code7, failing in multi-agent environments that utilize Cursor, Windsurf, Google Antigravity, GitHub Copilot, or native command-line workflows1. Conversely, legacy developer telemetry platforms such as WakaTime quantify wall-clock time spent in active editor buffers, an obsolete metric when an agent synthesizes complex microservices in seconds while the engineer supervises asynchronously1.

Qodewk addresses this architectural gap. Grounded in the thesis that the Git revision graph and local filesystem constitute the single source of truth across all coding agents, Qodewk functions as an open-source, universal telemetry and digital receipt generator. It passively captures code mutations, attributes line churn to human versus autonomous agents, reconstructs context consumption, calculates token expenditures across frontier models, and generates shareable "Developer Receipts" for standups, Pull Requests, and public developer networks7.

## 1\. Technical Feasibility & Telemetry Architecture

Qodewk is designed to operate locally with negligible CPU, memory, and disk I/O overhead. Developers reject background daemons that introduce perceptible latency into editor keystrokes, terminal shell prompts, or Git execution pipelines. The telemetry architecture operates at the intersection of operating system filesystem events, Git object storage, and Abstract Syntax Tree (AST) mutation engines.

### Git Diff Extraction and Filesystem Event Monitoring

Capturing code mutations across arbitrary branches without slowing down local developer machines requires a decoupled, two-tier observation pipeline consisting of passive operating system file monitoring and Git plumbing lifecycle hooks.

#### Passive Operating System Filesystem Observation

Relying exclusively on standard library recursive filesystem polling or continuous git status execution degrades CPU performance in repositories containing over 50,000 files. Qodewk utilizes a low-overhead, multi-threaded filesystem watcher compiled in native code, leveraging FSEvents on macOS, inotify via epoll on Linux, and ReadDirectoryChangesW via I/O Completion Ports on Windows.

Events are filtered immediately against a high-performance .gitignore matcher compiled with prefix trees. Non-code paths such as node\_modules, .git, target, dist, and vendor directories are pruned prior to event queue ingestion. Events are aggregated through a debounced sliding window of 1,500 milliseconds to consolidate atomic agent writes—such as multi-file workspace edits executed by Cursor Agent or Google Antigravity—into unified mutation frames1.

#### Git Lifecycle Hooks and Plumbing Interception

Operating system file watching captures ephemeral churn, but the Git revision graph remains the canonical arbiter of persistent state. Qodewk instruments non-intrusive Git hooks installed via core.hooksPath or symlinked inside .git/hooks/:

1.  post-commit: Extracts the exact commit SHA, parent commit, author timestamp, and executes a plumbing-level diff using native Git library bindings:
    Bash
    git diff-tree --numstat --summary --find-renames -M -B HEAD~1 HEAD

2.  post-rewrite: Intercepts rebases, interactive amendments, and squash merges, ingesting an input stream of old and new SHA pairs from standard input to maintain unbroken historical telemetry continuity12.
3.  pre-push: Performs an aggregate rollup calculation of branch deltas relative to the tracking remote, verifying that uncommitted working-tree churn is accounted for before egress.

To maintain zero latency on the developer's primary shell, Git hooks spawn the Qodewk background daemon using a detached asynchronous process (fork-exec with nohup and standard streams bound to /dev/null), returning control to the terminal within five milliseconds.

### Dual-Engine Token & Cost Estimation Algorithm

Coding agents differ in their observability. Qodewk executes a dual-engine estimation pipeline: Deterministic Session Harvesting when local agent transcripts are discoverable, falling back to Contextual Git and AST Inference when operating in closed or uninstrumented environments.

#### Deterministic Log Ingestion

When developers run agents with transparent local persistence, Qodewk ingests exact token counts directly from disk:

-   _Claude Code_: Ingests raw JSONL session logs located in `~/.claude/projects/<project-slug>/sessions/*.jsonl` It aggregates message.usage blocks (input\_tokens, output\_tokens, cache\_creation\_input\_tokens, cache\_read\_input\_tokens), deduplicating events across unique message.id and requestId identifiers to prevent double-counting across session retries5.
-   _Cursor IDE_: Ingests the state database located in ~/Library/Application Support/Cursor/User/globalStorage/state.vscdb and workspace-specific databases (workspaceStorage/\*/state.vscdb)9. Qodewk executes read-only SQLite connections with Write-Ahead Logging (WAL) compatibility to parse the cursorDiskKV table, extracting the conversation bubble array, requested model string, and generation token usage16.
-   _Google Antigravity & Windsurf_: Scrapes agent event artifacts and workspace session logs from their respective application support caches, extracting Gemini 3 Pro and Claude Sonnet usage matrices1.

### Privacy-First Guarantee: Zero Source Code Exfiltration

Enterprise adoption requires strict data containment. Developers working on proprietary trading engines, healthcare systems, or closed-source intellectual property reject tools that transmit source code over the network. Qodewk establishes a zero-trust privacy architecture enforced through five distinct mechanisms:

First, all parsing of Git diffs, AST traversals, and transcript log evaluations occurs strictly within the local host memory boundary. The application discards raw string buffers immediately after tokenizing and extracting structural metadata.

Second, file paths are never published or transmitted in raw form without explicit local configuration7. Every file path is transformed via keyed cryptographic hashing:

$M$

Receipt cards indicate structural categories without exposing internal organizational directory structures, customer names, or proprietary namespace nomenclature7.

Third, syntactic analysis extracts structural token metrics while stripping all variable identifiers, constant values, string literals, and code comments.

Fourth, the core Qodewk CLI binary is compiled without background network reporting routines in standard execution modes7. When invoked with the --local or --print flag, zero network sockets are opened7. Enterprise security engineers can audit the binary via static symbol analysis:

Bash

nm -u qodewk | grep -E "curl|http|socket|ssl"

confirming complete network dormancy during receipt generation7.

Fifth, telemetry records are preserved directly inside the local Git revision tree using custom namespaces (refs/notes/qodewk) rather than being transmitted to an external server11. The metadata travels only when the engineer deliberately pushes Git notes to their internal repository11.

### Analysis of Incumbent Deficiencies

Chit demonstrated that developers have a strong appetite for end-of-day work summaries7. However, its architecture is vulnerable: it is coupled entirely to Claude Code’s local disk log format (~/.claude/projects/) and distributed as a closed-source macOS-only application7. The moment a developer toggles into Cursor to resolve a frontend bug, spins up Google Antigravity to run multi-agent browser tests, or writes algorithmic logic by hand, Chit becomes blind1. Furthermore, when upstream model providers modify their JSON schemas, single-transcript parsers break8.

WakaTime remains tied to time-tracking primitives designed for manual text entry. Tracking the number of minutes an editor buffer remains active provides no signal regarding computational yield when an engineer prompts an agent, switches contexts, and returns to find dozens of files modified1. WakaTime cannot quantify token burn, prompt caching efficiency, reasoning depth, or computational cost per merged feature3.

Native IDE dashboards, such as Cursor’s usage page or GitHub Copilot’s enterprise console, are proprietary and siloed9. Their metrics exist primarily to justify invoice line items, calculate margin on bundled plans, and obscure cross-vendor expenditures.

### Unfair Advantages & Defensive Moat

DevReceipt establishes defensibility against native IDE features through three structural advantages:

Cross-vendor neutrality is the primary defensive barrier. Developer workflows are heterogeneous. Enterprise engineering teams rarely standardize on a single agent: backend engineers deploy Claude Code CLI in headless terminal multiplexers7, frontend designers work inside Cursor28, and QA architects orchestrate browser workflows inside Google Antigravity1. A vendor-owned tool has no strategic incentive to parse competitors' logs or calculate cost optimizations across external models1. Qodewk acts as an independent telemetry layer across the entire toolchain.

Grounding in the Git revision graph provides platform persistence. IDEs are transient interfaces, whereas the Git commit graph is the permanent historical ledger of software engineering. By storing receipt metadata directly inside Git objects using refs/notes/qodewk, Qodewk binds computational telemetry directly to code artifacts11. Telemetry persists across IDE switches, machine migrations, and repository clones without external database dependencies23.

Open-source verification creates an enterprise trust moat. Telemetry software inspecting developer workspaces requires transparent verification. Enterprise security teams will not approve closed-source background binaries that inspect working-tree file buffers. Qodewk’s permissive open-source codebase provides uncompromised security auditability.

## 5\. Edge Cases & Technical Risks

Operating at the operating system and version control layer requires addressing scale bottlenecks, attribution ambiguity, and history mutation challenges.

### High-Throughput Monorepo Scalability (100k+ Files)

Executing workspace traversals or naive Git status queries inside enterprise monorepositories containing over 100,000 files introduces significant I/O latency and terminal pauses. Qodewk implements three architectural mitigations to ensure responsiveness:

First, Qodewk scopes its filesystem event listeners strictly to the sub-tree path of the active sub-project rather than attaching to the repository root.

Second, Qodewk bypasses working-tree file index comparisons entirely during Git commits. Instead of invoking high-level commands (git status), it executes tree comparisons via git diff-tree -r --raw `<tree-ish-1>` `<tree-ish-2>`. This compares tree hashes directly in the Git object database, resolving differential file sets in sub-millisecond execution windows regardless of total repository size.

Third, filesystem scanning utilizes parallel directory traversal engines based on native prefix-tree ignore matchers, compiling ignore state across multi-nested .gitignore configurations without loading complete directory graphs into memory.

### Differentiating Human vs. AI-Agent Code Mutations

Accurately attributing code churn between human developers and autonomous agents is challenging when agents write directly to the local filesystem without leaving vendor-specific commit markers. Qodewk uses a multi-layered heuristic classification pipeline that assigns an agent confidence score ($M$) to every mutation hunk:

Temporal insertion velocity serves as the initial discriminator. Human engineers write code at an average rate of 40 to 80 words per minute, exhibiting natural variance, pauses, backspaces, and intermittent compilation checks. AI agents execute disk writes via buffer dumps, inserting 200 to 1,000 lines within a sub-second interval. When the Qodewk background daemon is active, burst insertion velocities exceeding 25 characters per millisecond trigger agent attribution flags.

Operating system process lineage inspects active file locks and process descriptors. If file write events to a code buffer originate from an ancestor process matching known agent binaries (claude, cursor, windsurf-agent, antigravity-worker, node), the resulting changes are attributed to that specific agent runtime7.

AST mutation burst topology evaluates syntax completeness. Human code construction involves intermediate syntax errors: a developer types a function signature, leaves it unclosed, defines a parameter, and incrementally refactors. AI agents generate structurally complete syntactic AST subtrees in a single file-flush event. Tree-sitter delta checks identify these instantaneous structural completions.

Git author and trailer introspection parses commit messages for emerging agent standard trailers:

Code snippet

Co-Authored-By: Claude Code `<noreply@anthropic.com>`
Agent-Client: Cursor/0.45.2 (darwin-arm64)
Generated-By: Google-Antigravity/2.0

If trailers exist, the engine assigns attribution with a 1.0 confidence score1.

### Version Control Mutability: Rebases, Squashes, and Merge Conflicts

Interactive rebasing (git rebase -i), squashing, and commit amending rewrite commit hashes, breaking external database linkages that associate telemetry with specific commit SHAs12.

Qodewk prevents telemetry disassociation by storing telemetry directly inside the Git repository using a dedicated Git Notes reference namespace: refs/notes/qodewk11. Git notes attach metadata blobs directly to Git object identifiers without altering the commit's content, tree, committer date, or resulting SHA29.

When a developer rebases or squashes, Git executes the post-rewrite hook12. Qodewk’s hook reads the rewrite map from standard input: The hook retrieves the refs/notes/qodewk JSON blobs from all old SHAs, computes a consolidated mathematical sum of all tokens, costs, files touched, and agent ratios, and attaches the aggregated JSON receipt blob to the `<new-sha>`11. If an amendment occurs (git commit --amend), the old telemetry is extracted and merged with the newly generated delta.

During merge conflicts, lines from both branches may be discarded, rewritten, or duplicated. Qodewk isolates conflict resolution churn: lines added or removed purely to resolve Git conflict markers (`<<<<<<<`, `=======`, `>>>>>>>`) are detected via regular expression matching and excluded from both human productivity metrics and agent generation token billing.

The architecture must satisfy two opposing technical requirements: the local CLI requires minimal memory footprint, sub-10-millisecond execution, and static distribution without runtime dependencies7; the web receipt generator requires rich typography, rapid image synthesis, dynamic social graph integration, and enterprise-grade data management38.

### Web Application & Receipt Generator Architecture

The cloud application layer utilizes Next.js 15 (App Router with React 19 Server Components). Pages render server-side for maximum performance, streaming receipt telemetry directly to the client.

The visual design system combines Tailwind CSS v4 with shadcn/ui (Radix primitives). The interface enforces thermal monospace styling, CRT phosphor visual modes, and high-density financial data tables.

The database and identity layer uses Supabase (PostgreSQL with Row-Level Security, authenticated via GitHub OAuth). Telemetry tables utilize composite primary keys on (org\_id, repo\_hash, commit\_sha). Supabase Vault manages developer API keys with hardware-level encryption.

The image generation engine pairs Satori with resvg-js38. While @vercel/og supports standard edge deployments, high-volume receipt sharing benefits from a dedicated server-side rendering pipeline:

1.  Qodewk defines the receipt layout using standard JSX and Tailwind CSS Flexbox primitives39.
2.  Satori converts the JSX virtual tree into a raw Scalable Vector Graphic (SVG), embedding variable monospace font buffers directly (JetBrains Mono)39.
3.  An SVG filter chain injects serrated receipt edges, paper texture noise, and an inline Code 128 barcode31.

## 8\. Strategic Conclusions & Future Outlook

The rapid proliferation of AI coding agents has decoupled developer productivity metrics from wall-clock time and disrupted infrastructure cost visibility1. In this unbundled development paradigm, tooling value is shifting from the point of code generation—which foundation models have commoditized—toward the layers of attribution, verification, and economic governance1.

Telemetry solutions coupled to proprietary IDE environments remain vulnerable to platform lock-in and obscured usage economics9. By decoupling observation from the editor and anchoring telemetry directly within Git primitives (refs/notes), Qodewk provides a durable, vendor-neutral telemetry layer for the multi-agent software era11.

For individual software engineers, Qodewk provides tangible proof of velocity and an automated counter to agent amnesia7. For engineering organizations, it delivers essential FinOps visibility, spend controls, and compliance governance required to scale autonomous agentic engineering safely and predictably3.
