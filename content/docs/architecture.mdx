## Architectural goal

Capture repository mutations with minimal local overhead while keeping proprietary source code and diffs off the cloud boundary by default.

## Local collector

The local CLI is the trust boundary.

Suggested local directory:

```text
~/.qodewk/
  config.json
  state.db
  events.jsonl
  cache/
```

SQLite is preferred for local state. JSONL is useful for append-only event logs and debugging/export.

## Capture strategy

Use three layers.

### 1. On-demand CLI

The primary MVP path:

```bash
qodewk
qodewk --json
qodewk share
```

Use Git commands or `simple-git` to inspect:

- status
- branch
- HEAD
- diff
- staged diff
- merge-base
- commit ranges

### 2. Git hooks

Use hooks for low-latency event recording:

- `post-commit`
- `post-merge`
- `post-checkout`

Hooks must never block Git on a network call.

Preferred flow:

```text
Git hook
  -> append local event
  -> exit immediately
  -> background uploader later
```

### 3. Filesystem watcher

`chokidar` may detect save activity, but should not be the final source of truth.

Correct division of responsibility:

> The watcher detects activity. Git proves mutation.

Use a dirty-path set, debounce rapid events, and only inspect targeted paths.

## Diff strategy

Avoid scanning the whole repository on every file save.

For active files:

```text
filesystem event
  -> dirty path
  -> debounce
  -> targeted Git diff
```

For committed work:

```text
git diff <base>..<head>
```

## Provider Discovery & Attribution Engine

Qodewk bridges Git mutations with AI telemetry through a hierarchical provider detection pipeline:

```text
+-----------------------------------------------------------+
| 1. Explicit CLI Flags (--provider, --model, --session)     |
+-----------------------------------------------------------+
                             | (if not provided)
                             v
+-----------------------------------------------------------+
| 2. Git Commit Footprints & Trailers                       |
|    - "Co-authored-by: Claude <noreply@anthropic.com>"     |
|    - "Generated with Cursor Composer"                     |
|    - Tool-specific commit message headers/trailers        |
+-----------------------------------------------------------+
                             | (if not found)
                             v
+-----------------------------------------------------------+
| 3. Local Provider Session Artifacts (Time-Correlated)     |
|    - Claude Code: ~/.claude/projects/ JSONL transcripts   |
|    - Cursor: SQLite composer storage in workspaceStorage  |
|    - Copilot: Editor session logs                         |
+-----------------------------------------------------------+
                             | (if no match)
                             v
+-----------------------------------------------------------+
| 4. Fallback: attributionMode = "unknown" (Confidence: 0)  |
+-----------------------------------------------------------+
```

### Discovery Rules
1. **Never guess without evidence:** If no session or trailer exists, mark provider as `unknown` rather than fabricating an attribution.
2. **Time-window correlation:** When scanning local session logs, only correlate sessions active within a configurable window (e.g. ±30 minutes) of the file touch/commit timestamp.
3. **Read-only discovery:** Provider log inspection is strictly read-only and never modifies third-party tool configs.

## Local Database Schema (`~/.qodewk/state.db`)

SQLite provides atomic, embedded state persistence for local tracking:

```sql
-- Tracked repositories
CREATE TABLE IF NOT EXISTS repos (
    id TEXT PRIMARY KEY,
    repo_hash TEXT UNIQUE NOT NULL,
    root_path TEXT NOT NULL,
    alias TEXT NOT NULL,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    last_observed_at DATETIME
);

-- Repository snapshots at commit or sync points
CREATE TABLE IF NOT EXISTS snapshots (
    id TEXT PRIMARY KEY,
    repo_id TEXT NOT NULL REFERENCES repos(id) ON DELETE CASCADE,
    branch TEXT NOT NULL,
    head_sha TEXT NOT NULL,
    base_sha TEXT,
    files_count INTEGER NOT NULL,
    insertions INTEGER NOT NULL,
    deletions INTEGER NOT NULL,
    captured_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- Linked provider session telemetry
CREATE TABLE IF NOT EXISTS provider_sessions (
    id TEXT PRIMARY KEY,
    repo_id TEXT NOT NULL REFERENCES repos(id) ON DELETE CASCADE,
    provider TEXT NOT NULL, -- anthropic, openai, cursor, copilot, etc.
    model TEXT,
    session_external_id TEXT,
    input_tokens INTEGER DEFAULT 0,
    output_tokens INTEGER DEFAULT 0,
    cached_tokens INTEGER DEFAULT 0,
    verified_cost REAL,
    confidence REAL NOT NULL DEFAULT 0.0,
    attribution_mode TEXT NOT NULL, -- observed, estimated, imported, verified, unknown
    captured_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- Local published receipts
CREATE TABLE IF NOT EXISTS receipts (
    id TEXT PRIMARY KEY,
    public_id TEXT UNIQUE,
    repo_id TEXT NOT NULL REFERENCES repos(id) ON DELETE CASCADE,
    head_sha TEXT NOT NULL,
    base_sha TEXT,
    payload_json TEXT NOT NULL,
    sync_status TEXT DEFAULT 'local', -- local, synced, failed
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX IF NOT EXISTS idx_snapshots_repo ON snapshots(repo_id);
CREATE INDEX IF NOT EXISTS idx_receipts_public_id ON receipts(public_id);
```

### Ephemeral / CI Environment Mode
In CI/CD environments (e.g. GitHub Actions) or read-only containers:
- If `CI=true` or `--no-db` is specified, Qodewk uses SQLite `:memory:` mode or bypasses database writes entirely.
- All metrics are computed strictly on-the-fly from the current git checkout range.

## Non-Destructive Git Hook Strategy

Git hooks must coexist peacefully with existing tooling (Husky, Lefthook, simple-git-hooks):

1. **Inspection before installation:** `qodewk hooks install` checks if `.git/hooks/post-commit` already exists.
2. **Boundary markers:** If a hook file exists, Qodewk appends an isolated script block wrapped in markers:
   ```bash
   # --- BEGIN QODEWK HOOK ---
   if command -v qodewk >/dev/null 2>&1; then
     (qodewk record-event --hook post-commit &) >/dev/null 2>&1
   fi
   # --- END QODEWK HOOK ---
   ```
3. **Guaranteed non-blocking:** The subshell runs in the background (`&`) and detaches standard streams so `git commit` finishes immediately with 0ms perceptible delay.
4. **Clean uninstaller:** `qodewk hooks uninstall` strips only the block between the markers, leaving the user's existing hooks intact.

## Receipt event

```ts
interface ReceiptEvent {
  id: string;
  repoHash: string;
  eventType: "working_tree" | "commit" | "merge" | "checkout" | "manual";
  branchHash: string;
  commitSha?: string;
  filesChanged: number;
  insertions: number;
  deletions: number;
  estimatedTokens?: TokenEstimate;
  estimatedCost?: CostEstimate;
  /** 0–1 confidence score; UI may render as % or Low/Medium/High */
  confidence: number;
  attributionMode: "observed" | "estimated" | "imported" | "verified" | "unknown";
  createdAt: string;
}
```

Canonical published receipt mutation fields use `files`, `insertions`, and `deletions` (see Receipt Protocol). Local events may keep `filesChanged` as an internal alias of `files`.

## Performance rules

1. Never parse every file on every save.
2. Cache file metadata and hashes.
3. Ignore generated/build directories.
4. Parse AST only for changed files.
5. Keep local watcher work asynchronous.
6. Keep Git hooks offline.
7. Batch cloud telemetry.

Recommended default exclusions:

```text
node_modules
.next
dist
build
coverage
vendor
.generated
```

Make exclusions configurable.
